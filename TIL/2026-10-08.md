## 1. 초보자를 위한 기구 설명: "사진 없이도 충분할까?"

**피드백**: "초보자는 '핵스쿼트 머신', 'T바 로우'가 뭔지 모른다. 사진이 있으면 좋겠다."

### 사진을 구하는 방법을 비교했다
| 방법 | 장점 | 단점 |
|---|---|---|
| 직접 촬영 | 정확하고 저작권 걱정 없음 | 26개 촬영 수고, 헬스장 허락·초상권 |
| Unsplash·Pexels | 출처 표시 의무 없음 | 특정 머신(핵스쿼트 등)은 찾기 어려움 |
| 위키미디어 공용 | 머신 사진이 꽤 있음 | 대부분 CC BY-SA라 **출처 표시 의무** |
| 사진 검색 링크 | 바로 가능, 저작권 문제 없음 | 앱 밖으로 나감 |

### 배운 것: CC 라이선스 출처 표시
- 표시할 4가지: **작성자 · 출처(원본 링크) · 라이선스(이름+링크) · 수정 여부**("크기 조정함")
- 표시 위치: 사진 **바로 아래** 한 줄 + 앱 안의 **"사진 출처" 페이지**(썸네일처럼 작은 이미지는 여기로 대신) + README
- **CC BY-SA**는 사진을 고쳐 쓰면 *그 사진만* 같은 라이선스로 공개하면 된다(앱 코드 전체가 아님).
- **NC(비영리)·ND(변경금지)**는 피한다. 나중에 서비스를 키우면 문제가 될 수 있다.
- 라이선스와 별개로 **얼굴이 알아볼 수 있게 나온 사진은 쓰지 않는다**(초상권).
- 출처 정보를 **데이터 한 곳(`photo` 필드)**에서 관리하면 표시 위치가 여러 곳이어도 어긋나지 않는다.

### 결론: 1단계만으로 충분했다
- 기구 카드에 **ⓘ** → 생김새 한두 줄 + 주로 쓰는 부위 + "이 기구로 하는 운동"(누르면 운동 방법) + **사진 검색 링크** + 시트 안에서 바로 선택
- 사진 조사(2단계)를 백그라운드로 시작했다가, 사용자가 "1단계로 충분히 전달된다"고 해서 **중간에 멈췄다**. 사진 칸(`photo` 필드)과 표시 기능은 만들어 두었으니, 나중에 데이터만 넣으면 된다.
- 교훈: **글 설명과 검색 링크로 먼저 내보내고, 부족하다는 피드백이 오면 그때 사진을 붙여도 된다.** 저작권 처리 비용이 큰 작업은 미뤄도 된다.

## 2. 웹앱을 "앱처럼": PWA와 공유 미리보기

### PWA에 필요한 것
- **manifest.webmanifest**: 이름, `display: standalone`(주소창 없이), 테마 색, 아이콘
- **아이콘**: 192·512px + **maskable 512px**(안드로이드가 원·둥근 사각형으로 잘라도 글자가 남도록 가운데 80% 안에 배치) + **apple-touch-icon 180px**(아이폰은 투명도 없는 정사각형, 모서리는 iOS가 깎음)
- 아이콘은 **Pillow + 맑은 고딕**으로 직접 그렸다. 저작권 걱정이 없다.

### 서비스 워커 캐시 전략
- **페이지 이동(navigation): 네트워크 먼저**, 실패하면 캐시된 `index.html` → 새로 배포하면 바로 반영되고, 지하 헬스장처럼 신호가 없을 때도 열린다.
- **해시가 붙은 빌드 파일(`/assets/…`)·아이콘: 캐시 먼저** → 파일 이름이 바뀌니 오래된 캐시 걱정이 없다.
- **배포 빌드에서만 등록**(`import.meta.env.PROD`). 개발 중에 캐시가 끼어들면 디버깅이 헷갈린다.
- 데이터는 원래 localStorage에 있으니 오프라인에서도 그대로 쓸 수 있다.

### 검증에서 배운 것
- 앱 내장 브라우저에서는 서비스 워커 등록이 "알 수 없는 오류"로 실패했다. 파일은 정상(200, JavaScript)이었다. **임베디드 브라우저는 서비스 워커를 막을 수 있다.** 그래서 `vite build` + `vite preview`로 파일 형식만 확인하고, 실제 동작은 **휴대폰에서** 확인했다.
- 배포 직후 `/manifest.webmanifest`가 `text/html`로 나왔다. 아직 옛 배포라 **SPA rewrite가 index.html을 돌려준 것**이었다. 새 배포가 반영되자 `application/manifest+json`. Vercel은 **실제 파일이 있으면 rewrite보다 파일을 먼저** 준다.
- 배포 완료는 `until` 루프로 content-type이 바뀔 때까지 기다리는 방식으로 확인했다.

### 카톡 공유 미리보기(Open Graph)
- `og:title`, `og:description`, `og:image`(**1200×630**, **절대 주소**), `og:url`, `twitter:card`
- 카톡은 미리보기를 **캐시**한다. 예전에 보낸 링크는 옛 모습이 나올 수 있고, 카카오 개발자 사이트의 **공유 디버거**로 초기화한다.

### 휴대폰에서 홈 화면에 추가할 때
- 아이폰: **Safari** 공유 버튼 → 홈 화면에 추가 / 안드로이드: 크롬 ⋮ → 홈 화면에 추가(앱 설치)
- **카톡 안의 브라우저에서는 메뉴가 없다** → "Safari로 열기", "다른 브라우저로 열기"
- 아이폰은 홈 화면 앱과 Safari의 **저장 공간이 따로**라서, 홈 화면 앱은 첫 화면부터 다시 시작한다.

## 3. 피드백으로 UI를 고치며 배운 것

### "보이지 않는 곳에 둔 선택지는 없는 것과 같다"
- 운동 중 종목 추가 시트 **맨 위에 "내 루틴에도 추가" 체크박스**를 뒀다.
- 피드백: 스크롤을 내린 상태로 담으면 **체크박스가 안 보여서 헷갈린다.**
- 수정: 체크박스를 없애고, **시트를 닫을 때** 방금 추가한 운동 목록과 함께 "내 루틴에도 추가할까요? [예] / [아니요, 오늘만]"을 묻는다.
  - [완료]뿐 아니라 ✕, 바깥 탭으로 닫아도 묻는다. 어떻게 닫아도 놓치지 않게 하려는 것이다.
  - 아무것도 추가하지 않았으면 묻지 않는다.
- 교훈: **결정은 그 결정이 필요한 순간에 물어본다.** 미리 설정해 두게 하면 놓친다.

### 컴포넌트 재사용: 같은 시트, 다른 상황
- 루틴 편집의 "운동 담기" 시트를 운동 중 "오늘 운동에 추가"에도 썼다.
- 상황 차이는 데이터로 표현했다: 오늘 이미 하는 운동(대체 전 원래 운동 포함)은 `locked: true` → "오늘 루틴에 있음"으로 잠금. 사용 중인 기구는 "기구 사용 중" 태그.
- **추가한 운동만 [빼기]**를 할 수 있고, 루틴에도 넣었던 운동을 빼면 루틴에서도 같이 뺀다. 반대 동작까지 맞춰 둬야 데이터가 어긋나지 않는다.

### 작은 표시 하나: ✎
- 분할 이름은 원래 탭하면 고칠 수 있었지만 제목처럼 생겨서 아무도 몰랐다. **✎와 점선 밑줄** 하나로 해결했다.

## 4. 박람회 준비: 형식을 알고 나서 방향이 바뀌었다

- 처음엔 시나리오 A·B를 **정해진 순서로 시연하는 대본**을 만들었다.
- 그런데 박람회가 **온라인(ZEP 메타버스)**이고, 방문자가 **노션 브로셔의 링크·QR로 각자 써보는** 방식이라는 걸 알게 됐다.
- 그래서 대본을 **소개 문장**으로 바꿨다.
  - 길이별 한 줄 소개(5초 / 15초 / 30초)
  - 핵심 기능 5개를 한 문장씩
  - **1분 만에 핵심 기능까지 가는 길**(추천 루틴 → [자리 없음])
  - 예상 질문 답변
- ZEP 방문자는 대부분 **PC**인데 앱은 **모바일용**이다 → 브로셔에 **"휴대폰 카메라로 찍어서 바로 써보기" QR 카드**를 표지와 마지막에 두 번 넣었다(`qrcode` 라이브러리로 생성).
- 노션 브로셔는 **마크다운으로 써서 붙여넣기**: 제목·목록·표·링크가 그대로 들어간다. 이미지 자리에는 "🖼 이미지: 파일명" 표시를 남겨 끌어다 놓게 했다.
- 교훈: **산출물을 만들기 전에 "어디서, 누가, 어떻게 볼지"를 먼저 확인하자.** 인쇄용인지, 온라인인지에 따라 같은 브로셔도 구성이 완전히 달라진다.

## 5. 자잘한 기술 메모

- **Windows 터미널 인코딩(cp949)**: 한글과 특수문자가 섞인 Python 스크립트를 표준입력(heredoc)으로 넘기면 깨질 수 있다. 스크립트를 **파일로 저장하고 `# -*- coding: utf-8 -*-`**를 붙여 실행했다.
- **테스트 선택자**: 목록에서 운동 이름을 찾을 때 이름 옆 ⓘ 버튼 글자까지 같이 읽혀서 못 찾았다. 어제에 이어 또 겪었다. **이름이 들어간 요소를 정확히 지정**해야 한다.
- **스크린샷 해상도**: 같은 화면도 캡처할 때마다 2배(750px)로 찍히거나 1배(375px)로 찍혔다. 홍보용 이미지는 **휴대폰에서 직접 캡처**하는 게 가장 선명하다.
- **추천 순서 다시 확인**: 대본에 결과를 적기 전에 지금 데이터로 추천을 다시 계산해서 확인했다. 데이터가 바뀌면 문서도 같이 바뀌어야 한다.
