## 1. 브로셔: 노션에 "HTML 파일 하나"로 올리기

### 이미지 규격과 이름
- 커버 380×270, 프로젝트명 150×100. 파일 이름은 `제1부_제3부스_유기민_…` 형식.
- 커버는 직접 만든 AI 일러스트를 쓰고, 그림 속 엉터리 로고("자리없GYM")만 **앱 로고로 갈아 끼웠다**(Pillow로 해당 영역을 덮고 다시 그림). AI 그림은 글자를 틀리게 그리는 경우가 많아서, 글자는 직접 넣는 편이 낫다.
- 작은 이미지(150×100)는 글자가 흐리면 안 보인다. 부제 색을 진하게, 띠 배경을 넣어 대비를 올렸다.

### 노션에서 깨지지 않게
- 노션은 HTML 첨부 파일을 미리보기로 보여준다. 그래서 **이미지를 전부 data URI(base64)로 넣고, 스크립트는 쓰지 않았다**. 파일 하나만 올리면 끝.
- 원본은 `brochure.template.html`(글) + `build_brochure.py`(이미지·회고 채워 넣기)로 나누었다. 글만 고치고 다시 빌드하면 된다.
- 글꼴은 Pretendard를 CDN으로 불러오고, 막히면 시스템 글꼴(맑은 고딕 등)로 떨어지게 했다. 레이아웃은 그대로 유지된다.

### 근거는 직접 받은 설문으로
- 구글 폼 42명 응답 중 최근 3개월 헬스장 이용자 33명 기준으로 계산했다. 예: 계획한 운동을 다 못 끝낸 적 있음 73%, 1년 미만은 대체 운동이 바로 안 떠오름 81%.
- 응답 파일에는 이름·연락처가 있어서 **저장소에 올리지 않았고**, 인용은 누군지 알 수 없게 다듬었다.

### 디자인 피드백: "글씨만 있어서 허전하다"
- 딱딱한 글꼴 → Pretendard, 줄 간격 넉넉하게, 섹션마다 이모지 아이콘.
- 문제 정의는 문장 대신 **상황 흐름 칩**(가슴 하는 날 → 벤치에 사람이… → 뭐로 대신하지? → 결국 못 끝냄)으로.
- 해결 방안 왼쪽 설명란은 **불편 태그 + 번호 제목 + 한 줄 요약 + "👉 이렇게 써요" 1·2·3 + 특징 칩**으로 채웠다. 오른쪽은 캡쳐.
- 숫자 카드 4개가 3+1로 줄바꿈되면 어색하다. 넓을 땐 4칸, 좁을 땐 2×2로 고정했다(`auto-fit` 대신).
- 말투는 회고와 문제 정의만 "~다.", 나머지는 "~요."로 두었다. 억지로 통일하지 않았다.

## 2. 서로 써보고 받은 피드백 반영

### ① "운동을 마쳤는데 또 하라는 것 같다"
- 완료 → [홈으로] → 바로 "오늘은 어떤 운동을 하나요?"가 나와서 **또 운동하라는 느낌**이었다. 다음 날 앱을 열어도 마찬가지.
- 해결: **앱을 열 때와 운동을 마친 뒤에는 대표 화면부터.** 대표 화면 주소를 `/`, 운동 고르기를 `/home`으로 나누었다. 완료 버튼은 [운동 마치기].
- 대표 화면은 **상황에 따라 버튼·문구가 바뀐다**: 처음(시작하기) / 기구만 등록(이어서 설정하기) / 설정 끝(시작하기 → 운동 고르기) / 운동 중(이어서 운동하기). 저장된 기구·루틴·진행 중인 세션만 보면 판단할 수 있어서 어렵지 않았다.
- 앱 안에서 움직일 때(설정 저장, 운동 화면의 뒤로)는 대표 화면을 거치지 않게 했다. "앱을 열 때"와 "앱 안에서 이동할 때"를 구분하는 게 핵심.
- 덤으로 왼쪽 위 로고를 누르면 대표 화면으로.

### ② "화살표 말고 꾹 눌러서 순서를 바꾸고 싶다"
- 직접 만들지 않고 **dnd-kit**을 썼다. 터치 센서에 `delay: 300ms, tolerance: 8px`을 주면 **꾹 누르기 전에 움직이면 스크롤, 0.3초 누르면 끌기**가 된다.
- 꾹 누를 때 휴대폰의 글자 선택·메뉴가 뜨지 않게 `select-none`, `-webkit-touch-callout: none`. 끌기 시작하면 `navigator.vibrate(30)`(안드로이드).
- 함정: 줄 전체에 키보드 끌기를 걸면 **줄 안쪽 버튼(세트 ±, ✕)의 Enter/Space까지 가로챈다.** 키보드 센서는 빼고, 키보드·스크린리더는 기존 ↑↓ 버튼을 쓰게 했다.
- 진짜 손가락은 PC에서 못 쓰니 `new Touch()` + `TouchEvent`로 "빠른 스와이프는 그대로 / 꾹 누르고 끌면 바뀜"을 둘 다 확인했다.

### ③ "이번 주·이번 달 운동 현황을 보고 싶다"
- 지금까지는 운동별 "마지막 기록"만 있었고 날짜별 기록이 없었다. 완료 화면에서 **마친 운동 1회 = 기록 1개**(날짜, 분할 이름, 세트, 볼륨, 바꾼 횟수)를 새로 저장한다.
- 같은 기록이 두 번 저장되지 않게 운동 세션에 `id`를 붙였다. React 개발 모드는 effect를 두 번 실행하는데, id로 걸러서 한 번만 저장되는 것을 확인했다.
- 날짜는 `toISOString()`(UTC) 말고 **기기 시간 기준 `YYYY-MM-DD`**로 만든다. 한국에서 새벽 운동이 전날로 찍히는 걸 막는다. 주는 월요일 시작.
- 디자인은 시안 3개(이번 주 도장 / 이번 달 잔디 / 숫자 요약)를 먼저 보여주고 골랐다: **이번 주 도장 카드 + 누르면 이번 달 달력 시트**.
  - 도장 안에는 분할 이름 앞 두 글자("가슴·삼두" → "가슴").
  - "지난주보다 +1" 배지는 **많을 때만**. 적을 때는 의욕이 꺾이지 않게 아예 안 띄운다.
  - 맨 아래 한 줄은 서비스 핵심 가치: "🔁 자리 없을 때 기다리지 않고 N번 바꿨어요".
  - 달력 진하기는 그날 세트 합계로 4단계(0 / 1~9 / 10~19 / 20+). 기본 루틴(운동 5개×3세트=15세트)이 중간이 되게 잡았다.
- 처음엔 카드가 데모를 **대신**하게 했는데, "소개는 남기고 아래 빈 공간에 보여 달라"는 피드백. 그런데 휴대폰 높이(812px)에서는 카드가 버튼 뒤로 가려졌다. **다시 온 사람은 기능 소개 3줄만 숨겨서** 첫 화면 안에 들어오게 했다. 스크린샷만 보지 말고 **요소 위치(getBoundingClientRect)를 재서** 가려지는지 확인한 게 도움이 됐다.

## 3. 자잘한 기술 메모
- 브로셔 캡쳐용으로 날짜를 고정할 때, 페이지 안에서 `window.Date`를 "인자 없이 부르면 고정 시각"인 클래스로 바꾸고 SPA 안에서 화면을 다시 그리게 했다. 앱 코드는 건드리지 않는다.
- 예시 기록을 넣어 캡쳐한 뒤에는 **원래 기록을 sessionStorage에 백업 → 캡쳐 → 복원**. 작업 중간에 멈추더라도 백업이 남아 있어서 복원할 수 있었다.
- 문구 하나("자리 없어도" → "자리 없을 때")를 바꿀 때는 앱·브로셔·결정 문서를 한 번에 검색해서 바꾸고, **그 문구가 찍힌 캡쳐도 다시 찍어야** 한다.
- 테스트 62개 → 72개(운동 기록 계산 함수 10개). 화면과 분리한 순수 함수(`src/lib/history.js`)라 날짜 경계(일요일, 월 첫날 요일)를 테스트하기 쉬웠다.
