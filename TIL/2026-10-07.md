# TIL 2026-10-07 — 자리없Gym MVP 하루 만에 만들고 배포하기

> "루틴은 있는데, 자리가 없다." 헬스장에서 기구가 사용 중일 때, 지금 쓸 수 있는 기구로 오늘 루틴을 바로 바꿔주는 모바일 웹 서비스를 PRD부터 배포까지 진행했다.

- 배포: https://jariupgym.vercel.app
- 저장소: https://github.com/ryugimin-0706/jariupgym
- 기술: Vite + React + Tailwind CSS v4 + React Router, localStorage/sessionStorage, Vitest, Vercel

## 1. 진행 방식에서 배운 것

### 코드보다 먼저 "모호한 점"을 질문으로 뽑기
PRD를 읽고 바로 코딩하지 않고, 기술 스택, 폴더 구조, 데이터 구조, 화면별 구현 순서를 먼저 정리했다. 그리고 **모호한 부분을 질문 17개로 뽑았다**.
- 예: "자리 없음"을 맨몸 운동에도 보여줄지, 미루면 어디로 가는지, 대체 후보가 동점이면 무엇을 먼저 보여줄지
- 답을 미리 정해두니 구현 중에 다시 고치는 일이 크게 줄었다.

### DECISIONS.md: PRD보다 우선하는 결정 기록
- PRD에 없거나 바뀐 내용을 **날짜와 함께** `DECISIONS.md`에 계속 쌓았다.
- "PRD와 충돌하면 이 문서가 우선"이라고 첫 줄에 적어 두니 기준이 하나로 정리됐다.
- 피드백으로 바뀐 것(버튼 색, 세트 기록 방식 등)도 왜 바꿨는지와 함께 남겼다.

### 단계별로 멈추고 확인하기
0단계(셋업과 로직) → 화면 4·5(핵심) → 6 → 1 → 3 → 2·2-B → 2-A 순서로 진행했다.
- **핵심 가치("자리 없음 → 대체")가 담긴 화면부터** 만들어서 일찍 배포했다.
- 단계마다 "무엇을 만들었고, 어떻게 확인하면 되는지"를 정리하고 멈췄다. 사용자가 직접 눌러보고 피드백한 덕분에 방향을 자주 바로잡을 수 있었다.

## 2. 기술적으로 배운 것

### git 커밋 vs GitHub vs push
| | 하는 일 | 위치 |
|---|---|---|
| 커밋 | 코드를 저장 시점(스냅샷)으로 기록 | 내 컴퓨터 |
| GitHub | 커밋을 올려두는 온라인 저장소 | 인터넷 |
| push | 내 커밋을 GitHub에 올리기 | 내 컴퓨터 → GitHub |

- GitHub 이메일을 숨기려면 Settings → Emails의 `숫자+아이디@users.noreply.github.com` 주소를 git 이메일로 쓴다.

### Vercel 주소는 두 종류
- `프로젝트-해시-계정.vercel.app`: **배포마다 생기는 미리보기 주소**. 로그인한 본인만 보인다(Vercel Authentication).
- `프로젝트.vercel.app`: **공식(프로덕션) 주소**. 누구나 접속할 수 있다. **공유는 이 주소로.**
- GitHub와 연결하면 push할 때마다 자동으로 다시 배포된다.
- SPA는 `vercel.json`에 rewrite를 넣어야 `/workout`에서 새로고침해도 404가 나지 않는다.

### Vite + React ≠ Next.js
- Next.js는 서버 기능(SSR, API)이 있는 프레임워크다.
- 이번 MVP는 서버, DB, 로그인이 없어서 **브라우저에서만 도는 SPA(Vite)**가 더 단순했다.

### Windows PowerShell에서 `npm`이 안 될 때
- `npm.ps1 ... 스크립트를 실행할 수 없으므로` 오류는 PowerShell 실행 정책 때문이다.
- 설정을 바꾸지 않으려면 **`npm.cmd`**로 실행하면 된다. 바꾸려면 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

### 규칙 기반 추천 (AI 없이)
- 후보 조건: 같은 세부 타깃, 내 헬스장에 있는 기구, 지금 사용 중이 아님, 오늘 루틴에 없음
- 점수: 같은 동작 패턴 +3, 다른 기구 +1, 맨몸 −1
- 동점이면 **프리웨이트 우선**, 그다음 데이터 순서
- **대체 관계를 데이터로 저장하지 않고** 부위와 패턴으로 계산하니, 운동을 38개에서 87개로 늘릴 때 데이터만 추가하면 됐다.
- "부위"를 두 층으로 나눴다: 탭(가슴/등/하체…)과 매칭용 세부 타깃(허벅지 앞/뒤, 엉덩이, 종아리…). 세부 타깃을 나눠야 카프 레이즈가 스쿼트 대체로 나오지 않는다.

### 테스트는 "데모가 깨지지 않게" 하는 곳에만
- 추천 로직과 운동 세션 reducer만 Vitest로 테스트했다(최종 58개).
- 데모 시나리오의 추천 순서를 테스트로 고정해 두니, 데이터를 늘렸을 때 **시나리오 A 순서가 바뀐 걸 바로 알아챘다**.
- 데이터 무결성 테스트도 효과가 컸다: 모든 세부 타깃에 운동 2개 이상, 모든 기구가 묶음에 정확히 하나, 모든 운동에 설명이 있는지.

### localStorage / sessionStorage
- 모든 접근을 try/catch로 감싸서 사생활 보호 모드나 손상된 값에서도 앱이 멈추지 않게 했다.
- 기구와 루틴은 localStorage에 두고, **진행 중인 운동은 sessionStorage**에 둔다. 헬스장에서 화면이 꺼지거나 새로고침해도 이어서 할 수 있다.
- 저장 구조에 `version`을 넣어 나중에 구조가 바뀔 때를 대비했다. 예전 세션도 읽을 수 있게 변환 함수(`setLogOf` 등)를 두었다.

### 모바일 UI에서 배운 것
- **아이폰 Safari는 버튼을 눌러도 입력칸 포커스가 빠지지 않을 수 있다.** 그래서 "칸을 벗어날 때 반영"하면 값이 사라질 수 있다. **치는 대로 바로 반영**하도록 바꿨다.
- **밝은 민트(#2EC4B6) 바탕에 흰 글씨는 대비가 약 2.3:1**이라 권장 기준(4.5:1)에 못 미친다. 주 버튼은 네이비로, 밝은 민트는 진행 상태 표시에만 쓰도록 정리했다.
- 터치 영역은 최소 44px, 주 버튼은 오른쪽 아래(한 손 엄지 위치)로 통일했다.
- CSS `transform`이 걸린 요소 안에 `position: fixed`를 두면 기준이 그 요소로 바뀐다. 그래서 바텀시트 안에서 또 다른 시트를 열면 위치가 어긋난다. **시트는 페이지 단위에서 띄웠다.**
- 가로 스크롤은 PC 마우스 휠로는 안 넘어간다. 휠을 가로 스크롤로 바꿔주고, 넘길 내용이 있는 쪽 가장자리를 흐리게 처리했다.
- 애니메이션은 `prefers-reduced-motion`을 존중해서, 동작 줄이기 설정이 켜진 기기에서는 최종 모습만 보여준다.
- 운동 이모지는 오래된 휴대폰에서 깨지지 않게 Unicode 11 이하만 쓴다. 🪢는 Windows에서 네모로 나왔다.

### 저작권 고려
- 운동 방법 그림은 인터넷 이미지를 그냥 가져다 쓰지 않았다. **짧은 글 설명 + 유튜브 검색 링크**로 시작하고, 그림은 공개 라이선스 이미지만 검토하기로 했다.

## 3. 사용자 피드백으로 바뀐 것

| 피드백 | 반영 |
|---|---|
| 직접 입력한 운동이 담겼는지 모르겠다 | 담기 시트 안에 "추가됨 ✓" 목록 + ✕로 빼기 |
| 담은 운동을 바로 취소하고 싶다 | [✓ 담음]을 다시 누르면 빠지게 |
| 운동 종목이 적다 | 기구 15→26개, 운동 38→87개, 복근 탭, 하체 세부 부위 |
| 기구 고르기가 불편하다 | 종류별 묶음(프리웨이트/상체 머신/하체 머신/케이블) + 묶음별 모두 선택 + 머신 부위 표시 |
| 스크롤하면 몇 개 골랐는지 안 보인다 | 하단에 "N / 26개" + [다음] |
| 운동 방법을 알려줬으면 | 3단계 설명 + 주의점 + 영상 검색, ⓘ 버튼 |
| 첫 화면이 바로 기구 선택이라 어색하다 | 데모 카드 애니메이션이 있는 첫 화면 |
| 버튼 색이 촌스럽다 | 네이비 + 코랄 테두리로 정리 |
| 세트마다 체크하고, 무게와 횟수도 기록하고 싶다 | 세트 줄(무게/횟수/✓), 세트 추가·삭제, 지난 기록 불러오기, 총 볼륨 |

- 피드백을 받으면 바로 만들지 않고 **시안을 2~4개 그려서 비교**한 뒤 고르게 했다. 예: 첫 화면 3안, 버튼 색 4안.
- 세트 기록은 다른 운동 앱(짐워크)의 방식을 참고하되, 우리 기능(자리 없음, 대체)과 맞물리게 다시 설계했다. 예: 대체할 때 끝낸 세트는 유지하고, 남은 세트는 횟수만 이어가고 무게는 비운다.

## 4. 실수와 교훈

- **브라우저 탭 확인 없이 스크립트를 실행했다가**, 사용자가 열어둔 실제 배포 사이트 탭의 저장 데이터를 테스트 값으로 덮어썼다.
  - 교훈: 저장소를 건드리는 스크립트는 **탭을 지정하고, 주소(origin)가 localhost인지 먼저 확인**한 뒤 실행한다.
- 테스트용 선택자를 느슨하게 써서("추가"가 들어간 첫 버튼) 엉뚱한 버튼을 눌렀다. **정확한 선택자**를 써야 테스트 결과를 믿을 수 있다.
